# Statistics teaching materials

Open `../index.html` to choose the schedule, lecture notes, class slides, homework, test banks and answer keys, or Excel competency checks under Statistics. Open `class-slides.html` for the 36 section PDFs aligned to OpenStax **Introductory Statistics 2e**. The course contains 854 portrait discussion pages.

Selected sections cover Chapters 1–8. Chapter 9 has one conceptual overview deck (9.0), rather than the full chapter’s computational procedures. Chapter 1 lab resources 1.5 and 1.6 are included in the review.

Each page contains one definition, concept, or problem with a focused question. All prompt content stays in the upper half of US Letter portrait pages; the lower half is clear for pen annotations. The instructor provides explanations and worked solutions.

The [October 2026 textbook coverage audit](docs/textbook-coverage-audit.md) maps section terminology, chapter glossary entries and major textbook problem types to specific revised PDF pages.

## HTML lecture notes

`lecture-notes.html` indexes the pilot notes for Sections 3.4 and 3.5 in `lessons/`. They follow the textbook directly, independently of the existing slides. Each textbook Example and Try It is represented in order: 3.20–3.23 for contingency tables, and 3.24–3.30 for tree and Venn diagrams. Questions are condensed classroom adaptations, with full static worked solutions beneath them.

The notes reuse `../tsm/styles.css` and `../tsm/solutions.js`: double-click, double-tap, Enter, or Space toggles each solution while reserving its natural height. `lecture-notes.css` adds responsive tables and SVG diagrams. All SVG marks inherit currentColor to remain concealed with the answer text. Keep solutions initially white on white, retain the shared controls, and preserve the source links and CC BY-NC-SA attribution. These hand-maintained HTML files are not generated by the slide builder.

Intentional corrections: Example 3.23 uses explicitly fictional incident counts, rather than summing crime rates across years, while retaining the same table and question structure. Try It 3.25 uses 11/51 on the second face-card branch, giving P(FF) = 132/2652; all second-draw denominators are 51. Example 3.25 explicitly distinguishes P(B on second | R on first) from the reversed condition. Example 3.30 treats the supplied blood-type percentages as textbook exercise assumptions and omits clinical donor claims.

## Editing and rebuilding

Edit the appropriate `slides/source/chapter-NN.json`. From this course folder, run:

```bash
python -m pip install -r requirements.txt
python scripts/build_slides.py
```

To rebuild a selected set of chapters:

```bash
python scripts/build_slides.py --chapters 2 3 4 5 6 7 8 9
```

The shared renderer is `../scripts/slide_builder.py`. It requires DejaVu Sans fonts in `/usr/share/fonts/truetype/dejavu` (Debian/Ubuntu package `fonts-dejavu-core`). For another platform, change `FONT_DIR` in the shared renderer. Formulas and charts remain vector graphics in the PDFs.

`slides/coverage.json` records the planned sections; builds reject missing or unexpected sections. `docs/slide-specifications.md` records the presentation preferences. Chapter coverage documents under `docs/` map textbook objectives and prerequisite connections, including the small amount of extra emphasis given to ideas needed later. Those instructor notes are not printed on the slides.

## Unit tests and public question banks

Read and follow [Statistics Test Specifications](specifications/Statistics_Test_Specs.md) before generating any statistics test, retake, diagnostic, final, or practice version. The approved default is a two-page student test with a narrow answer column, a single-page two-column key matching the student-page row geometry, and a completely blank key verso. These specifications supersede older separate-answer-sheet and two-page-key formats.

Include this instruction in the student directions of every future test/exam and practice test/exam, including unit tests, retakes, diagnostics, and finals: **"Students may use a basic, non-scientific calculator only."** A basic four-function calculator is permitted; scientific, graphing, and CAS calculators are not permitted.

For every newly generated test/exam or practice test/exam version, independently choose a random five-digit integer from 10000 through 99999 as its version identifier. Apply this to single versions and every version in a requested batch, including unit tests, retakes, diagnostics, and finals. Do not use timestamps, sequential numbering, lettered labels, or batch suffixes; no numerical ordering is required. Duplicate identifiers are acceptable; no uniqueness check or registry is required. Use the same identifier on the student test, corresponding answer key, and filename when practical.

Four units pair Chapters 1-2, 3-4, 5-6, and 7-8. Chapter 9 is assignment or participation material, not tested. Each [public unit bank](question-banks/index.html) contains 100 multiple-choice questions, with student-visible answers, explanations, and source-slide references. Each unit has exactly two student HTML options: a complete bank with answers and explanations visible after each question, and a 10-question practice-test generator. The generator draws one question from each of ten topic pools (currently ten questions per pool), shuffles the questions and choices, and provides a score and explanations when students check their answers. Version links reproduce the same questions and choice order. Structured JSON files support building and validating the same questions.

Questions must not depend on a particular sample-quartile or sample-percentile convention, including whether an odd sample's median is included in either half, interpolation, and tie/rank choices. Supply any needed quartiles, percentile cutoffs, or fences explicitly, or choose data and answer options whose keyed choice is unchanged across reasonable methods. Use approximate language for sample percentile positions and middle-half interpretations; do not require exact observation counts at quartile boundaries or fence-equality minutiae. Continuous-model percentiles may still be assessed from their model probabilities. The October 15, 2026 audit is recorded in `question-banks/source/convention-audit.json`.

Rebuild from the Teaching root with `python stats/scripts/build_question_banks.py`. Editable question sources are in `question-banks/source/`. The build publishes HTML banks and generators, never bank or assessment PDFs. Instructor-requested printable tests are produced separately and saved outside the published Teaching repository. The existing PDF renderer requires an explicit output destination outside this repository. Keep future print tests aligned to the same ten pools in `question-banks/source/test-blueprint.json`; do not add student PDF links or AI generation prompts. Shared course navigation preserves direct bank and competency-check links when rebuilding slides or homework. The browser generator is `question-banks/test-generator.js`. Run `node stats/tests/question-bank-generator.cjs` to check pool coverage, shuffling, correct-answer remapping, and saved-version reproducibility.

## Excel competency checks

The [nine competency checks](excel-competency-checks.html) have detailed HTML preparation directions, a roughly five-minute face-to-face demonstration, and alternative variations. They cover matching count/mean/median/modes, matching mean/range/spread by a visible calculation, frequency tables and charts, target means and medians, sample standard deviation, contingency tables and probabilities, random-trial simulation and the law of large numbers, normal probabilities, and sample-size/confidence-interval comparisons. Google Sheets differences appear in parentheses. Rebuild the index and directions with `python stats/scripts/build_competency_checks.py`; styling is in `excel-checks.css`.

Each skill page includes a JavaScript assignment generator. Checks 1–2 show a minimal target-only prompt and a separate setup-and-reasoning help link. Checks 3–9 also let students choose a practice variation, copy source data or the assignment, and reopen the exact task from its version link. Their live check view hides learning examples and practice self-checks while the instructor observes the spreadsheet demonstration. It is a display option, not an exam-security mechanism. No workbook is uploaded or automatically graded.

Check 1 generates a hidden dataset of 50–100 numbers in [0, 1000] and displays only its count, exact integer mean, median, and one or two modes. Random variation selects one or two modes with equal probability. A mode differs from both mean and median by at least 100. Students construct column A in a blank workbook with COUNT, AVERAGE, MEDIAN, and MODE.MULT; count, median, and the complete mode set must match exactly. Mean tolerance is instructor judgment. Hidden observations are never rendered or included in copied assignments or practice answers. Its problem appears immediately after the title, followed by a regenerate button and requirements. Spreadsheet setup and reasoning are on `excel-checks/01-match-summary-help.html`; the problem page uses `match-summary-page.js` and has no variation selector, live-check toggle, version controls, or answer panel. Existing page URLs remain stable as displayed check numbers shift by one, preserving saved seeds and their original generation rules.

Check 2 replaces data preparation at the existing `excel-checks/01-prepare-data.html` URL. Its independent pure generator is `excel-checks/match-spread-generator.js`; its minimal browser display is `match-spread-page.js`. Ten hidden observations produce a mean, exact range, and one spread measure rounded to four decimal places. Population standard deviation, population variance, sample standard deviation, and sample variance are equally likely. Independently, bell-shaped, endpoint-concentrated, strongly right-skewed, and strongly left-skewed datasets are equally likely. Randomized positions, scale, and location vary the targets within [0, 1000]. Neither witness data nor its shape is rendered. Students construct their own ten values; matching the hidden shape is not required. Mean and spread tolerance is instructor judgment, parallel to Check 1; count and range are exact. The separate `02-match-spread-help.html` teaches column A observations, B repeated whole-column AVERAGE, C deviations, D squared deviations, E their sum, F division by n or n − 1, and G square root only for standard deviation. Range uses MAX minus MIN separately. Built-in variance/standard-deviation shortcuts do not satisfy this check.

The original pure generators are in `excel-checks/generators.js`; browser controls for Checks 3–9 are in `excel-checks/check-page.js`. The legacy data-preparation generator is retained only to keep the original v1 generation rules stable; the replacement Check 2 does not load it or interpret legacy version parameters. The HTML builder preserves all controls and learning directions. Check 4 includes mean/median, mean/sample-standard-deviation, minimum/maximum/sample-standard-deviation, median/extremes, and mean/extremes constructions with 5–10 observations. Targets and feasible follow-ups come from witness datasets, which appear only in the expandable practice self-check. Mean and standard-deviation targets allow 0.05 absolute error; other targets are exact. Other checks vary data size, labels, requested summaries or conditionals, model inputs, and follow-up changes. Datasets are synthetic.

Checks 3–9 assignment links use generator version `v=1`, an eight-digit hexadecimal seed, and the requested variation. Preserve the v1 generation rules and random-number call order when making compatible changes; if a future version changes those rules, retain v1 support for existing links. Invalid or unsupported links on those pages fail visibly rather than silently changing a saved task. Simulation trial outcomes in Excel remain random even when the assignment link is fixed.

Run `node stats/tests/competency-generators.cjs` from the Teaching root to validate 37,000 seeded assignments, all variation families, copied-data structures, achievable construction targets, and feasible follow-up changes. No npm packages are needed for the generator tests. Browser QA should also cover all nine pages, every variation, regenerate/reload, copying with a manual fallback, live check view, and a narrow mobile viewport.

Run `node stats/tests/match-spread-generator.cjs` to independently verify 16,000 replacement Check 2 tasks: ten bounded values, attainable summaries, population/sample and variance/standard-deviation calculations, geometric shape checks, and all sixteen shape/measure combinations at balanced frequencies.
